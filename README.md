# Объезд

Семестровый проект: простая кроссплатформенная ретро-игра.

Жанр — объезд препятствий на трассе, как в играх начала 80-х
(например, Donkey из каталога old-games.ru), но правила свои.

Машина едет по трёхполосной трассе. Нужно уворачиваться от встречных
машин и камней и подбирать канистры с бензином. Скорость постепенно растёт.

## Правила

- `<-` и `->` — перестроиться в соседнюю полосу, `Esc` — выход.
- `[V]` — встречная машина, `(@)` — камень: столкновение отнимает жизнь.
- `[F]` — канистра: +20 бензина (не больше 99).
- Бензин тратится по ходу движения. Игра кончается, когда нет жизней
  (в начале 3) или бензина (в начале 60). `R` — начать заново.
- Каждые 150 единиц пути скорость растёт (до 4).
- Счёт — пройденный путь `DIST`.

## Архитектура

Программа состоит из трёх частей:

1. **Платформа** — всё, что зависит от ОС: вывод экрана, клавиатура,
   пауза между кадрами (`src/platform.h`).
   - `src/plat_unix.c` — Linux: escape-коды терминала и `termios`;
   - `src/plat_win.c` — Windows: консоль, `conio.h`;
   - `src/plat_web.c` — браузер (Emscripten, WebAssembly): экран — текст
     в элементе `<pre>`, клавиши — события браузера.
2. **Ядро** на C, не зависит от ОС:
   - `src/vm.c` — стековая виртуальная машина;
   - `src/forth.c` — транслятор Forth-подобного языка в байт-код ВМ;
   - `src/core.c` — загружает скрипт, хранит экран 40x22 символа
     и выполняет системные вызовы скрипта (рисование, клавиши, случайные числа).
3. **Игровая логика** — скрипт `scripts/game.fs` на Forth-подобном языке.
   Ядро вызывает его слово `init` один раз при запуске и слово `tick`
   каждый кадр (20 кадров в секунду).

Ячейка ВМ всегда 32 бита (`int32_t`), поэтому логика работает одинаково
на 32- и 64-битных процессорах.

## Язык логики

Программа — это набор слов. Слово определяется так:

    : имя ... ;

Числа кладутся на стек, слова снимают аргументы со стека
и кладут результат. Пример:

    \ комментарий до конца строки
    : square ( n -- n*n ) dup * ;
    : main 5 square 1 + ;       ( на стеке будет 26 )

Встроенные слова:

| Слово | Стек | Действие |
|---|---|---|
| `+ - * / mod` | `a b -- c` | арифметика |
| `= < >` | `a b -- f` | сравнение, результат 1 или 0 |
| `and or` | `a b -- c` | побитовые И, ИЛИ |
| `not` | `a -- f` | 1, если a = 0, иначе 0 |
| `dup` | `a -- a a` | копия вершины |
| `drop` | `a --` | убрать вершину |
| `swap` | `a b -- b a` | поменять местами |
| `over` | `a b -- a b a` | копия второго элемента |
| `@` | `addr -- x` | прочитать ячейку памяти |
| `!` | `x addr --` | записать ячейку памяти |

Остальные конструкции:

| Конструкция | Что делает |
|---|---|
| `variable имя` | объявляет переменную (только вне определений); её имя кладёт на стек адрес |
| `array имя N` | массив из N ячеек; имя кладёт адрес первой, элемент i — `имя i + @` |
| `'A'` | код символа |
| `s" текст"` | кладёт адрес и длину строки |
| `усл if ... then` | выполняется, если на стеке не 0 |
| `усл if ... else ... then` | ветвление |
| `begin ... усл until` | повторять, пока на стеке 0 |

Системные слова (их выполняет ядро):

| Слово | Стек | Действие |
|---|---|---|
| `cls` | `--` | очистить экран |
| `put` | `x y ch --` | поставить символ |
| `text` | `x y addr len --` | вывести строку (`s" ..."`) |
| `num` | `x y n --` | вывести число |
| `key` | `-- k` | нажатая клавиша: 1 влево, 2 вправо, 3 вверх, 4 вниз, иначе код символа, 0 — ничего |
| `rnd` | `n -- r` | случайное число от 0 до n-1 |

Пример — факториал и сумма от 1 до 10:

    : fact ( n -- n! ) dup 1 > if dup 1 - fact * then ;

    variable i
    variable s
    : sum10 ( -- 55 )
        0 s ! 1 i !
        begin s @ i @ + s ! i @ 1 + i ! i @ 10 > until
        s @ ;

## Платформы

| ОС | Процессор | Графика | Ввод | Сборка |
|---|---|---|---|---|
| Windows | x86-64 (64 бита) | консоль | клавиатура, `conio.h` | `mingw32-make` |
| Linux | x86-64 (64 бита) | терминал, escape-коды | клавиатура, `termios` | `make` |
| Linux | i386 (32 бита) | терминал, escape-коды | клавиатура, `termios` | `make game32` |
| Web | WebAssembly (32 бита) | HTML-страница | клавиатура браузера | `make web` |

ОС трёх категорий: Windows, Unix (Linux), Web. Процессоры разной
разрядности: 64-битный x86-64 и 32-битные i386 и WebAssembly.
Ядро и скрипт игры одинаковые для всех платформ, отличается только
файл `src/plat_*.c`.

## Сборка

Нужны `gcc` и `make`.

Linux:

    make
    make game32     # 32-битная версия, нужен пакет gcc-multilib

Windows (MinGW):

    mingw32-make

## Запуск

    ./game          # Linux
    game.exe        # Windows

По умолчанию загружается `scripts/game.fs`, другой скрипт можно передать
аргументом: `./game myscript.fs`. Выход — Esc.
Окно терминала должно быть не меньше 40x23 символов.

## Веб-версия

Нужен [Emscripten](https://emscripten.org/). Сборка:

    make web
    mingw32-make web EMCC=путь/к/emsdk/upstream/emscripten/emcc.exe   # Windows

Получается один файл `game.html` (скрипт игры встроен внутрь),
его можно открыть в браузере двойным щелчком.

## Тесты

Модульные тесты лежат в каталоге `tests`:

- `test_vm.c` — команды ВМ, переполнения и обработка ошибок;
- `test_forth.c` — транслятор: числа, слова, массивы, условия, циклы,
  строки, комментарии, ошибки.

Запуск:

    make test

### Фаззинг

`tests/fuzz.c` генерирует 100 000 случайных программ из команд ВМ
и 100 000 случайных текстов для транслятора (из набора слов языка,
граничных чисел и «мусора») и выполняет их. Проверяется, что ВМ
не падает, не зависает и всегда остаётся в корректном состоянии.
Входные данные зависят от seed, поэтому любую находку можно повторить.

    make fuzz                 # случайный seed
    ./run_fuzz 42             # конкретный seed

В Linux фаззер стоит запускать с проверкой памяти и неопределённого поведения:

    make fuzz FUZZFLAGS="-g -fsanitize=address,undefined -fno-sanitize-recover=all"

Что нашёл фаззер и что исправлено:

1. Бесконечный цикл в программе вешал ВМ — добавлено ограничение числа
   шагов (`MAX_STEPS`, ошибка `too many steps`).
2. Переполнение при `+ - *` (неопределённое поведение в C) — арифметика
   считается в беззнаковых числах с переполнением «по кругу».
3. Деление `-2147483648 / -1` роняло программу на x86 — деление
   на -1 обрабатывается отдельно.

Для каждой находки добавлен модульный тест.
